# 中文合同的结构与惯例

排版之外的东西。写错了不影响文档能不能打开，但会让对方觉得这份合同不是常做生意的人写的。

## 整体结构

```
封面页          文书名 + 合同编号 + 甲乙方 + 签订日期
────── 分页 ──────
缔约主体        双方全称、统一社会信用代码、法定代表人、注册地址、联系方式
鉴于条款        一段，交代双方背景与缔约目的
正文条款        第 1 条 … 第 N 条
签章区          （本行以下无正文，仅供签章之用）+ 甲乙方分组
────── 分页 ──────
附件            附件一、附件二……每个另起一页
```

## 封面

三组信息用**不同对齐**区分，这是关键：

- **合同编号** 靠右
- **甲方 / 乙方** 靠左，且两行互相对齐
- **签订日期** 单独下沉，略缩进

全部居中会把这种区分抹平，看起来像海报而不是合同。

标题居中加粗放大，压在页面约 1/4 处，不要贴顶。

## 缔约主体块

字段用两列表格排，标签列和值列各自对齐。**不要**用全角空格手动对齐——注册地址和统一社会信用代码长度差很多，空格对齐一定会散。

每方一张表比「项目 | 甲方 | 乙方」三列表好：地址这类长字段能拿到整行宽度。表头行直接用「甲方（客户）| 单位名称值」，省掉一行。

## 条款编号

两种通行写法，选一种贯穿全文：

| 写法 | 层级 | 适用 |
| --- | --- | --- |
| `第 1 条` / `1.1` / `(a)` | 三层 | 技术服务、SaaS、数据类合同 |
| `一、` / `1.` / `(1)` | 三层 | 传统公文风格，制造业与国企常见 |

交叉引用要跟着一致：写了「第 5.5 条」，标题就必须是「第 5 条」而不是「五、」。**改编号体系会牵动全文所有交叉引用**，动手前先 grep 一遍。

## 签章区

```
（本行以下无正文，仅供签章之用）


甲方：
授权代表：
日期：        年     月     日


乙方：
授权代表：
日期：        年     月     日
```

要点：

- **竖排堆叠**，甲方组和乙方组上下分开，中间留白。不要并排——盖章需要空间，公章直径 4cm 左右。
- **「本行以下无正文」这句必须有**，防止在空白处补写内容。
- 整块不能被分页劈开（见 `openxml-gotchas.md` 的 keepNext 章节）。
- 日期留成「　年　月　日」的填空格式，别预填。
- 附件如果是独立的服务确认单 / 订单，末尾也要有自己的签章区。

## 占位符

用 `【】`，不用 `[]`、`____` 或高亮：

```
甲方：【甲方签约主体全称】
统一社会信用代码：【　　　　　　】
乙方于收到款项后 【10】 个工作日内开具发票
```

待议的数字也用 `【10】`——发出去对方一眼看出哪些是可谈的。

## 附件

- 每个附件**另起一页**
- 正文里要有一条「附件均为本合同不可分割的组成部分」，并列出附件清单
- 附件编号变动时（比如删掉一个附件），全文交叉引用要同步——这是最容易漏的地方

## 框架合同 + 确认单的结构

要做长期合作时，把合同拆成两层比每次签一份完整合同好：

- **正文**：分工、数据与隐私、知识产权、保密、验收、责任、争议解决。签一次，两年。**不含任何价格。**
- **附件《第 N 号服务确认单》**：本期的价格、额度、期限、里程碑。

正文里写一句「后续新增工作包只需按附件格式签署新的服务确认单，正文与其他附件不再变动」。以后每单只签一页。

**价格不进正文**的另一个好处：单价写进正文就成了可援引的基准，下一单想涨价没法解释。放在确认单里，配一句「本单价不构成对后续工作包的报价，不得被援引为续约、续充或扩量的价格基准」。

## 税费口径

境内 B2B 服务合同主流写**含税价（价税合计）**，因为采购方按实付金额批预算。但最稳的写法是**三个数都写**：

```
不含税金额   ¥47,169.81
增值税 6%    ¥2,830.19
价税合计     ¥50,000.00（合同金额）
```

两种阅读习惯都能直接用。签字时才发现一方以为含税、一方以为不含税，是最常见的纠纷，差额就是税率那几个点。

## 排版之外常被漏掉的条款

不是法律建议，只是清单——写中文商务合同时容易漏：

- **视为验收**：对方在 N 个工作日内未提异议即视为通过。没有这条，验收和尾款会被无限拖。
- **能力边界**：明确写出不承诺什么。技术服务合同尤其重要。
- **责任上限**：以已实际支付的服务费为限。
- **保密期限**：一般 3 年；但原始数据与交付物通常写无期限。
- **附件效力**：明确附件是不可分割的组成部分，以及冲突时的效力顺序。
