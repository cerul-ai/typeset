# 排版参数与取值依据

全部参数集中在 `scripts/build.py` 顶部的常量块。改风格改那里，不要散落到各处。

## 页面

| 项 | 值 | twips | 说明 |
| --- | --- | ---: | --- |
| 纸型 | A4 | 11906 × 16838 | pandoc 默认是 Letter，中国合同必须 A4 |
| 上下边距 | 2.54 cm | 1440 | Word 中文默认 |
| 左右边距 | 3.00 cm | 1701 | 中文合同常见 3.00–3.18cm，留装订边 |
| 页眉距边界 | 2.00 cm | 1134 | |
| 页脚距边界 | 1.50 cm | 850 | |
| 正文宽 | — | 8504 | 估表格列宽时用得上 |

1 cm = 567 twips，1 pt = 20 twips，字号的 `w:sz` 是**半磅**（12pt → 24）。

## 字体与字号

| 用途 | 中文 | 西文 | 字号 | 说明 |
| --- | --- | --- | ---: | --- |
| 正文 | 宋体 | Times New Roman | 12pt（小四） | |
| 标题 1（文书名 / 附件名） | 黑体 | Times New Roman | 16pt，居中加粗 | 方案 C 用 22pt |
| 标题 2（条款） | 黑体 | Times New Roman | 14pt，加粗 | |
| 标题 3 | 黑体 | Times New Roman | 12pt，加粗 | |
| 表格 | 宋体 | Times New Roman | 10.5pt（五号） | 比正文收一号，密集表格才不挤 |
| 页脚 | 宋体 | Times New Roman | 9pt | |

**为什么中文用宋体、西文用 Times New Roman**：宋体的拉丁字形很差，而中文合同里往往夹着大量英文术语和数字。分开指定 `w:eastAsia` 和 `w:ascii/w:hAnsi` 就能各用各的。

**为什么标题用黑体**：宋体正文 + 黑体标题是中文正式文书的标准搭配（公文用黑体标题 + 仿宋正文）。只靠加粗区分层级，在有表格的密集文档里会显得很平。

字体名用 `宋体`/`黑体` 而不是 `Songti SC`/`Heiti SC`——前者 Word 在 Windows 和 macOS 上都认，后者只在 macOS 上有。

## 间距

| 项 | 值 |
| --- | --- |
| 行距 | 1.5 倍（`w:line="360" w:lineRule="auto"`） |
| 段后 | 6pt（`w:after="120"`） |
| 标题 1 段前/段后 | 18pt / 10pt |
| 标题 2 段前/段后 | 14pt / 7pt |
| 表格内行距 | 1.17 倍（`w:line="280"`） |

1.5 倍行距不只是好看——对方法务要在行间批注。

## 颜色

| 用途 | 值 |
| --- | --- |
| 正文与标题 | `000000` 纯黑 |
| 表格边框 | `BFBFBF` |
| 表头底纹 | `F2F2F2` |
| 引用块 / 公式块底纹 | `F7F7F7` |
| 灰色注记 | `595959` |

**标题必须是纯黑。** pandoc 默认的 `0F4761`（Word 2024 Aptos 主题的青蓝）是最显眼的"这不是正式文书"信号。

## 四套封面与签章方案

正文版式四套相同，差别只在封面、签章区、页眉横线。

### A · 复刻参考版

封面用**不同对齐区分三组信息**：合同编号靠右、缔约方靠左且互相对齐、签订日期单独下沉并略缩进。签章区竖排堆叠、只给标签、留白供盖章。页眉有横线。

这是国内公司合同最常见的范式。默认选它——对方法务看着眼熟，审得快，改得少。

### B · 严格对齐版

封面用无框表格做「标签 | 值」两列，值带下边线当填空线，四行严格对齐。签章区也是无框表格，甲乙并排，字段带填空线。

适合打印后手填的场景。缺点是并排签章留白不足，盖章会挤。

### C · 公文庄重版

封面信息块加外边框，标题放大到 22pt，底部一句「本合同经双方签字并盖章后生效」。签章区竖排 + 独立的「（此处加盖公章）」提示。

最有仪式感，适合给投资人或更正式的场合。

### D · 现代简洁版

封面左对齐信息块，上下用细线包夹，不居中。签章区竖排 + 行内「（盖章）」标注。没有页眉横线。

最好看，但在一堆合同里辨识度低（没有页眉线）。

## 表格

- 全边框 `BFBFBF` 0.5pt，表头行底纹 `F2F2F2` + 黑体加粗
- 单元格内边距：上下 60、左右 90 twips
- 所有行 `cantSplit`（不跨页断开）
- 列宽由 markdown 分隔行的连字符数量决定，按内容量分配

估列宽：中文全角字在 10.5pt 下约 210 twips，加单元格边距 180。「统一社会信用代码」8 个字需要约 1860 twips，正文宽 8504——所以这一列至少要占 22%。

## 与 pandoc 默认值的差异一览

| 项 | pandoc 默认 | 本 skill |
| --- | --- | --- |
| 纸型 | Letter | A4 |
| 标题颜色 | `0F4761` 青蓝 | `000000` 纯黑 |
| 标题加粗 | 否 | 是 |
| 标题字号 | 20 / 16 / 14pt | 16 / 14 / 12pt |
| 西文字体 | Aptos | Times New Roman |
| 中文字体 | 主题回退 | 宋体 / 黑体 |
| 行距 | 单倍 | 1.5 倍 |
| 页眉页脚 | 无 | 横线 + 页码 |
| 表格边框 | 简单 | 全边框 + 表头底纹 |
| 孤行控制 | 关 | 开 |
